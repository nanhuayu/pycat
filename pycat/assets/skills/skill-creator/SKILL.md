# 创建和改进技能

适用于用户明确要求提炼可复用方法的任务。先检查已有技能；一次性的任务记录、事实或偏好不应变成技能。

1. 明确何时使用、何时不使用、输入、输出和验收条件。优先从实际完成的任务提炼必要步骤。
2. 写简短而有辨识度的 description。正文包括步骤、关键选择、失败恢复和结果检查，避免重复通用知识及硬编码的个人路径、密钥或会话内容。
3. 名称使用 3–64 位小写字母、数字与连字符。面向项目的方法使用 project，全局通用的方法使用 global。
4. 使用可用的 skill__manage 工具提交 create 或 patch 候选。patch 仅适用于允许 Agent 修改的已有技能。不得通过文件写入绕过候选评估与发布流程。
5. 为“设置 → 工具与能力 → 技能 Skills → 已安装 → 更多 → 候选方法”的比较准备至少四个不同样例，覆盖正常、失败、不适用和独立保留样例，并提供可检查的输出或文件结果。只有经过实际评估的结果才能报告为通过。
6. 告知候选位置、改进内容与尚未验证的部分，由用户在设置中完成评估和发布。没有可用的管理工具时提供可审阅草稿，不宣称已生效。

技能提供方法，不新增权限。外部技能和内置技能保持只读；需要人工定制时先在设置中复制为用户技能。资源按需读取，避免一次加载无关材料。
