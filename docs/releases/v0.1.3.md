# PyCat v0.1.3

> GitHub Release 发布说明

## 建议发布标题

`PyCat v0.1.3`

## 建议 Tag

`v0.1.3`

## 发布内容

PyCat v0.1.3 是一个稳定性与运行契约修复版本，重点处理 Settings 关闭崩溃、
Channel 只有推理而没有最终回复，以及模型输出预算被旧默认值过早截断的问题。

### 重点更新

- **Settings 关闭稳定性**：dirty refresh 改为由 Dialog 拥有的 single-shot timer，
  关闭时停止 tracking；ProviderEditor 的后台任务统一复用 `BackgroundJob`，
  QObject receiver 已销毁或回调被放弃时不会让异常逃出 Qt 的 `QRunnable.run()` 边界。
- **Channel 显式完成协议**：Channel 默认重新使用 `agent__complete` 提交最终回复；
  普通阶段文本不再吞掉后续完成结果，阶段消息与最终消息按消息身份和正文去重。
- **输出预算统一**：无显式覆盖时产品默认输出从 4,096 调整为 65,536；
  模型档案的 `max_output_tokens` 只作为能力上限，再按总上下文窗口夹紧。
  DeepSeek/OpenAI-compatible 的 reasoning 与正文继续共享真实 `max_tokens`，
  不发送不存在的通用 `reason_token_limit` 字段。
- **Provider 终态归一化**：Responses、Chat Completions、Anthropic 和 Ollama 的
  finish reason、usage、失败、取消和截断统一进入 `Message.metadata`。
  截断响应不再执行可能不完整的 tool call，也不会被误判成成功完成。
- **失败上下文隔离**：只有 reasoning、空正文和未完整响应有明确中断语义；
  未完成的 reasoning、tool call 和 reasoning metadata 不会污染下一次模型请求。
- **桌面操作调整**：会话侧栏右键菜单可以直接在资源管理器中打开有效工作目录；
  Composer 的附件入口改用更直观的加号图标。

### 兼容性与打包

- `core.version.__version__` 是唯一版本来源；CLI、GUI、wheel 和 Windows 包元数据均使用 `0.1.3`。
- PyCat 继续使用 **GNU Affero General Public License v3.0 only (AGPL-3.0-only)**。
- Windows 压缩包同时包含 `pycat.exe` 与 `pycat-cli.exe`。当前构建未代码签名，
  首次运行出现 SmartScreen 常规提示属于预期现象。

## 使用方式

1. 下载并解压 `pycat-0.1.3-windows-x64.zip`。
2. 运行 `pycat.exe` 启动桌面应用。
3. 运行 `pycat-cli.exe --version` 验证压缩包中的命令行入口。

## 验证

- 排除既有 Windows Shell 生命周期模块后，完整源码集合 `1005 passed`；GUI 子集 `279 passed`。
- `compileall`、工具目录检查和 93 份受管 Markdown 文档检查通过。
- 完整门禁仍在 `tests/runtime/test_process_runtime.py` 中出现 11 个失败和 1 个 teardown 错误：
  Windows 子进程继续占用 `process_logs/*.log`，触发 `WinError 32`，另有一项进程树存活断言不稳定。
  本版本没有把该既有问题伪装为全量通过，也没有在发布任务中顺带重构 Shell 生命周期。
- wheel 元数据确认为 `pycat 0.1.3 / AGPL-3.0-only`，共 359 个条目，
  不含测试、开发文档、本地状态、缓存或调试文件。
- Nuitka 4.0.8 使用 MSVC 14.3 构建；`pycat.exe` 与 `pycat-cli.exe` 的
  FileVersion/ProductVersion 均为 `0.1.3.0`。
- 构建目录与解压后的 ZIP 均通过 `pycat-cli.exe --version`、`list modes` 和
  嵌入式 `python_exec` worker 探针；解压包共 122 个文件，内容白名单审计通过。

## 已知问题

- Windows Shell 后台进程的日志句柄关闭和进程树终止仍需单独收敛；在此之前，
  完整 `scripts/check.py -Scope full` 会在 `tests/runtime/test_process_runtime.py` 报告上述失败。
- Windows 构建尚未代码签名，发布下载应以本页 SHA256 校验值为准。
