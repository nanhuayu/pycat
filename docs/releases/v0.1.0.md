# PyCat v0.1.0

> Release notes for GitHub Release

## Suggested release title

`PyCat v0.1.0`

## Suggested tag

`v0.1.0`

## Release body

PyCat v0.1.0 是 0.1 系列的第一个版本，聚焦 **架构收敛、Agent 运行时重组、渠道平台化、GUI 包重命名、配置契约化、记忆候选审查、模型管理与桌面体验增强**。相较 v0.0.7，本版本不只是新增功能，而是将此前散落在 `runtime`、`task`、`services`、`ui`、`channel/sources` 中的能力重新收束到更清晰的长期目录结构。

### 本版本定位

v0.1.0 的核心目标是把 PyCat 从“功能持续增长的早期原型”推进到“可继续扩展的桌面 Agent 工作台”：

- 一套明确的 Agent 执行核心，替代早期 `core/runtime` 与 `core/task` 的重叠边界。
- 一套应用服务与仓库边界，替代顶层 `services/` 的松散组织。
- 一套渠道平台协议，统一 QQ、WeChat、Feishu、Telegram 的接入、投递、会话绑定和运行调度。
- 一套契约模型，集中描述 agent、tooling、content、config、channel、mode、skill 和 session state。
- 一套更完整的桌面交互层，覆盖系统托盘、快捷键、会话搜索、模型编辑、调试追踪和工具调用展示。

## Highlights

- **目录结构正式收敛**：`ui/` 重命名为 `gui/`，顶层 `services/` 迁入 `core/app/services/`，应用仓库迁入 `core/app/repositories/`，旧 `core/runtime` 与 `core/task` 拆分到 `core/agent/*`。
- **Agent 运行时重组**：新增 `core/agent/run`、`core/agent/request`、`core/agent/tooling`、`core/agent/policy`、`core/agent/events`、`core/agent/delegation`，将请求构建、运行状态、工具循环、子 Agent 调度和事件追踪分层。
- **契约模型集中化**：新增 `models/contracts/`，把 `RunPolicy`、`RunStatus`、`ToolSelectionPolicy`、`ToolPermissionConfig`、`ChannelConfig`、`ModeConfig`、`Skill`、`ArchivedContentRecord` 等公共结构迁入统一契约层。
- **渠道平台化**：新增 `ChannelCatalog`、`ChannelGateway`、`ChannelPlatformBackend`、`ChannelMessageProcessor`、`ChannelSessionResolver` 等模块，QQ、WeChat、Feishu、Telegram 均迁入 `core/channel/platforms/`。
- **WeChat iLink 支持增强**：新增 WeChat iLink 登录、轮询 transport、官方/实验协议路由与会话绑定能力，并将 WeChat 客户端版本升至 `0.1.0`。
- **记忆候选审查系统**：新增 `core/memory/`，支持 memory candidates、advisor、审查/采纳/拒绝流程，避免运行时派生事实直接污染长期记忆。
- **模型管理升级**：新增模型选择、Provider 编辑、远端模型目录、模型 profile 编辑能力，设置页可以更细粒度地维护 provider/model 配置。
- **桌面体验增强**：新增系统托盘、快捷键帮助、会话搜索、调试追踪弹窗、Assistant Run 展示组件、工具调用视图和工作流胶囊组件。
- **搜索配置增强**：搜索配置支持最大结果数动态设置，搜索页和服务层同步更新。
- **发布版本升级**：CLI、GUI 应用版本和 WeChat 客户端版本统一升至 `0.1.0`。

## 从 v0.0.7 以来的主要变更

### 新增

- **Agent 包结构**：新增 `core/agent/run/runtime.py`、`engine.py`、`state.py`、`stop_policy.py`，提供统一的 `AgentRuntime`、运行结果和停止原因。
- **请求管线**：新增 `core/agent/request/pipeline.py`，集中处理消息准备、上下文注入、通道提示段和 LLM 请求构建。
- **工具执行分层**：新增 `core/agent/tooling/executor.py`、`loop.py`、`result_recorder.py`，工具执行、结果归档和运行事件记录不再混在单一任务类中。
- **子 Agent 调度**：新增 `core/agent/delegation/runner.py`、`subagent.py`，能力调用和子任务调度具备更明确的上下文边界。
- **Debug trace**：新增 `core/agent/events/debug_trace.py` 与 `gui/dialogs/debug_trace_dialog.py`，支持追踪上下文维护、工具调用和运行阶段信息。
- **应用容器与仓库**：新增 `core/app/container.py`、`core/app/repositories/*`，集中管理 conversation、provider、settings、MCP、search config 和 workspace session。
- **应用服务层迁移**：新增 `core/app/services/*`，将 conversation、context、provider、search、skill、channel 等服务从顶层 `services/` 收拢到应用边界内。
- **配置迁移**：新增 `core/config/migrations.py`，并引入 `jsonschema` 依赖，为后续配置 schema 演进提供基础。
- **渠道平台定义**：新增 `core/channel/platforms/*/definition.py`，每个渠道的字段、展示信息和连接模式由平台定义描述。
- **渠道运行组件**：新增 `core/channel/gateway.py`、`host.py`、`scheduler.py`、`turn_runner.py`、`worker.py`、`replies.py`、`bindings.py`、`session_resolver.py`。
- **内容与归档迁移**：新增 `core/content/archive_store.py`、`archive_view_service.py`、`pending_preview.py`，归档内容从 `core/context` 迁入更贴近内容域的位置。
- **上下文构建重组**：新增 `core/context/builder.py`、`compression.py`、`maintainer.py`、`request_context_planner.py`、`providers/*`，把 prompt providers 从 `core/prompts/providers` 迁入上下文域。
- **记忆模块**：新增 `core/memory/service.py`、`advisor.py`，长期记忆和候选记忆从状态服务中拆出。
- **状态模块**：新增 `core/state/artifact.py`、`todo.py`、`work_trace.py`、`operations.py`，将 artifact/todo/work trace 操作按领域拆分。
- **技能模块拆分**：新增 `core/skills/discovery.py`、`manifest.py`、`prompt.py`、`resources.py`、`routing.py`，技能发现、清单解析、提示注入和资源读取分离。
- **工具文档生成**：新增 `core/tools/documentation.py`，用于生成和管理工具文档说明。
- **GUI 组件**：新增 `gui/widgets/tool_call_view.py`、`workflow_capsule.py`、`assistant_run_widget.py`、`inline_question_view.py`、`markdown_view.py`、`image_thumbnail.py`。
- **设置页组件**：新增 `gui/settings/components.py`、`provider_editor.py`、`model_catalog_dialog.py`、`model_profile_dialog.py`、`mcp_editor.py` 和多组 settings pages。
- **系统托盘和快捷键**：新增 `gui/runtime/tray_controller.py`、`gui/shortcuts.py`、`gui/dialogs/shortcut_help_dialog.py`。
- **统一主题文件**：新增 `assets/styles/theme.qss` 和 `assets/icons/checkbox-check.svg`。

### 优化

- **导入路径更清晰**：GUI 代码统一走 `gui.*`，应用服务统一走 `core.app.services.*`，公共契约统一走 `models.contracts.*`。
- **运行状态语义更明确**：`TaskStatus` 演进为 `RunStatus`，停止原因通过 `RunStopReason` 表达，CLI 可根据运行状态返回更准确的退出码。
- **工具权限与选择策略契约化**：`ToolSelectionPolicy`、`ToolPolicy`、`ToolPermissionConfig`、`ToolAvailabilityContext`、`ToolDescriptor` 迁入 `models/contracts/tooling.py`。
- **模型目标表达统一**：新增 `ModelTarget`，能力、模式和委托运行可以统一表达 primary、auxiliary、explicit 模型目标。
- **上下文压缩更可解释**：压缩报告字段和 metrics 结构更集中，归档索引条目与待处理预览策略更明确。
- **工具结果展示更友好**：工具调用视图支持文件变更、子 Agent 摘要、待处理预览和精确视图标签，UI 中的工具输出不再只是纯文本堆叠。
- **Inspector 面板替代 StatsPanel**：右侧面板从统计展示升级为检查器视角，通道、产物、任务与工具运行信息的标题和摘要更清晰。
- **模型编辑体验提升**：Provider 编辑页支持模型历史、取消操作、远端目录拉取与手动 profile 编辑。
- **通道会话绑定改进**：渠道消息进入统一 gateway 后，由 session resolver 与 bindings 模块处理会话定位和回复目标。
- **WeChat 连接体验改进**：二维码连接状态、轮询、登录 session 和 iLink headers 更稳定。
- **搜索配置 UI 收敛**：搜索页可配置最大结果数量，并由 `SearchConfig` 与搜索服务共同承载。
- **窗口和输入体验增强**：窗口几何、快捷键、发送/取消、图片缩略图、Markdown 展示和输入区细节进一步整理。
- **样式体系统一**：深色/浅色主题从分散文件收敛到统一主题文件，内置图标和组件尺寸进一步标准化。

### 修复

- 修复旧 `ui`、`services`、`runtime`、`task` 多套边界并存导致的导入路径与职责重复问题。
- 修复渠道平台代码分散在 `core/channel/sources` 下，难以统一声明字段、连接模式、投递和生命周期的问题。
- 修复通道运行时直接承担过多队列、会话、回复和调度职责的问题。
- 修复长期记忆与运行时派生候选事实混在一起的问题，候选记忆现在需要显式审查。
- 修复部分工具结果归档只有最终摘要、缺少 pending preview 和双阈值策略的问题。
- 修复模型配置编辑撤销、取消和远端模型同步体验不完整的问题。
- 修复通道卡片标题与详情文本过长时显示不清晰的问题。
- 修复老样式文件重复维护深色/浅色主题导致的显示不一致问题。

## 架构说明

### 新目录边界

```text
main.py / main_cli.py
  -> gui/                         # PyQt6 桌面界面
  -> core/app/                    # 应用容器、仓库、服务
  -> core/agent/                  # Agent 运行时、请求管线、工具循环、子 Agent
  -> core/channel/                # 渠道 gateway、平台定义、投递和会话绑定
  -> core/content/                # 内容归档、视图、pending preview
  -> core/context/                # 上下文构建、压缩、providers
  -> core/memory/                 # 长期记忆与候选记忆审查
  -> core/state/                  # todo/artifact/work trace 操作
  -> models/contracts/            # 公共契约模型
```

### Agent 运行链路

```text
RuntimePolicyBuilder
  -> AgentRuntime
  -> RequestPipeline
  -> AgentRunEngine
  -> ToolCallCoordinator
  -> ToolExecutor
  -> ToolResultRecorder
  -> RunEvent / DebugTrace
```

这个拆分让 GUI、CLI、渠道入口和子 Agent 调度可以共享同一套运行语义，同时减少旧 `Task` 类承担过多职责的问题。

### 渠道平台链路

```text
ChannelCatalog
  -> ChannelPlatformBackend
  -> ChannelGateway
  -> ChannelMessageProcessor
  -> ChannelSessionResolver
  -> ChannelTurnRunner
  -> ChannelReply / Delivery
```

QQ、WeChat、Feishu、Telegram 现在都以平台插件形态接入。平台负责协议细节，gateway 负责队列、绑定、调度和会话运行，降低后续新增渠道的成本。

### GUI 重命名

`ui/` 已迁移为 `gui/`。这不是单纯改名，而是为了把桌面界面和核心运行时边界分开：

- GUI 只负责 PyQt6 呈现、用户交互和 presenter。
- 核心执行走 `core/agent`。
- 应用数据访问走 `core/app/repositories`。
- 业务服务走 `core/app/services`。
- 公共数据结构走 `models/contracts`。

## Breaking changes

- 插件、脚本或扩展如果引用 `ui.*`，需要改为 `gui.*`。
- 引用顶层 `services.*` 的代码需要迁移到 `core.app.services.*`。
- 引用 `core.runtime.*` 或 `core.task.*` 的运行时代码需要迁移到 `core.agent.*` 或 `models.contracts.agent`。
- 引用 `core.channel.sources.*` 的渠道代码需要迁移到 `core.channel.platforms.*`。
- 引用 `models.state`、`core.config.schema`、`core.tools.catalog`、`core.tools.permissions` 的公共类型需要改用 `models.contracts.*` 中的新位置。
- 旧的 `assets/styles/dark_theme.qss` 和 `assets/styles/light_theme.qss` 已移除，主题样式收敛到 `assets/styles/theme.qss`。

## How to use

1. 下载 `pycat-0.1.0-windows-x64.zip`。
2. 解压到本地目录。
3. 双击运行 `pycat.exe` 启动 GUI。
4. 在终端中运行 CLI：

```text
pycat-cli.exe --version
pycat-cli.exe list modes
pycat-cli.exe list providers
pycat-cli.exe list tools
pycat-cli.exe run "你好，介绍一下当前能力"
```

源码开发环境中：

```text
python main.py
python main_cli.py --version
python main_cli.py list modes
```
